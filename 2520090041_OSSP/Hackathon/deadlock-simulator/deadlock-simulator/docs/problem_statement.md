# Problem Statement
Deadlocks freeze processes that hold resources while waiting for each other. Students find the Coffman conditions, resource-allocation graphs, detection and recovery abstract, and static textbook examples hide the reasoning.
**Objectives:** (1) model processes/resources with multiple instances; (2) detect deadlock with correct algorithms and explain why; (3) distinguish detection, avoidance (Banker's) and cycles; (4) recover (terminate/preempt) and *verify* the result; (5) make it demonstrable and reproducible.
**Scope:** educational simulator, single machine, in-memory model with JSON history. Not a real OS kernel tool.
**Users / use cases:** OS students and instructors (lab demos, quizzes via Challenge Mode), hackathon judges, self-study.
